# nfl_data_py is intentionally NOT listed here — it's vendored, not
# pip-installed. See nfl/vendor/README.md for the full reasoning: 0.3.3's
# own PyPI metadata pins pandas<2.0, which conflicts outright with
# pandas 2.x below (confirmed directly — pip refuses the combination with
# ResolutionImpossible, no ordering or extra flags fix it within a single
# `pip install -r requirements.txt`). This file used to document a manual
# two-step local `pip install -r requirements.txt && pip install --no-deps
# nfl_data_py==0.3.3` workaround — that only ever worked for local dev,
# since it depended on someone remembering to run the second command by
# hand. A single-command build (Vercel's, and any other standard one)
# only ever ran the first step, silently never installing nfl_data_py at
# all — which is exactly what broke the Vercel deployment. Vendoring
# removes the two-step process entirely, for local dev and Vercel alike:
# a plain `pip install -r requirements.txt` is now sufficient everywhere.
